# 入门笔记(来时的路) - CSAPP 学习笔记 3 扩展

1.32位系统使用八字节数据类型

在 32 位系统中，自然字大小（即指针或寄存器的大小）为 32 位或 4 个字节，
处理像 long long int 这样的八字节数据类型由于其尺寸较大而涉及多个步骤。

在 32 位系统上读取或写入 8 字节数据类型时，处理器会执行多次内存访问以检索或存储完整值。 
以下是处理方式的总体概述：

拆分数据：八字节数据类型被拆分为两个四字节部分。 低位字节存储在一个存储位置，高位字节存储在另一存储位置。

加载和存储操作：要读取八字节数据类型的值，处理器会执行两个单独的四字节加载操作，以从内存中检索该值的两部分。 
类似地，当存储八字节值时，处理器执行两个单独的四字节存储操作以将两个部分写入内存。

对齐注意事项：有效访问八字节数据类型通常需要正确的对齐。 
在许多系统上，八字节数据类型应在可被 8 整除的地址上对齐，以确保最佳性能。 
未能对齐数据可能会导致内存访问速度变慢，甚至在某些体系结构上导致程序崩溃。

性能影响：与访问四字节数据类型相比，在 32 位系统上访问八字节数据类型需要更多内存访问，并且可能需要更多指令。
 这可能会影响涉及八字节数据类型的操作的性能，尤其是在紧密循环中或处理大量数据时。

需要注意的是，在 32 位系统上处理 8 字节数据类型的具体实现细节可能因处理器、编译器和操作系统而异。 
编译器可以采用各种策略来优化较大数据类型的处理，例如利用SIMD（单指令、多数据）指令或特定于目标体系结构的其他技术。

总体而言，虽然 8 字节数据类型可以在 32 位系统上使用，但在使用它们时考虑潜在的性能影响和对齐要求非常重要。

补充:
在 32 位系统上处理 8 字节数据类型（如 double）时，处理相对简单。 与 64 位系统相比的主要区别在于，
在 32 位系统上，数据可能会被分成两个单独的 4 字节内存位置以进行加载和存储。

它的一般工作原理如下：

拆分数据：8 字节双精度值被拆分为两个 4 字节部分。 低位字节存储在一个存储位置，高位字节存储在另一存储位置。

加载和存储操作：读取和写入双精度值涉及单独的 4 字节加载和存储操作。 
处理器执行两个单独的操作来检索或存储值的两个部分。

对齐注意事项：正确的对齐对于在许多系统上有效访问双精度值非常重要。 
通常，双精度值应在可被 8 整除的地址上对齐，以获得最佳性能。 未能对齐数据可能会导致内存访问速度变慢，
甚至在某些架构上导致程序崩溃。

值得注意的是，在 32 位系统上处理 double 值通常比处理 long long int 等 8 字节整数类型更有效。 
浮点运算（包括双精度运算）通常由硬件浮点单元支持，硬件浮点单元可以比基于软件的方法更有效地执行必要的运算。

然而，重要的是要考虑到，与 64 位系统相比，32 位系统上的浮点运算性能可能仍然会稍慢一些。 
这是由于字大小较小，限制了每次内存访问中处理的数据量，并可能影响浮点计算的整体性能。

总之，虽然在 32 位系统上处理 8 字节数据类型（例如 double）可能会对性能产生一些影响，
但该处理通常是可管理的，并且可以使用适当的内存访问和对齐策略有效地执行。


2.二进制小数表示方法

文字描述该过程如下：将该数字乘以2，取出整数部分作为二进制表示的第1位；然后再将小数部分乘以2，将得到的整数部分作为二进制表示的第2位；以此类推，知道小数部分为0。
特殊情况： 小数部分出现循环，无法停止，则用有限的二进制位无法准确表示一个小数，这也是在编程语言中表示小数会出现误差的原因
 

0.6 * 2 = 1.2 ——————- 1
0.2 * 2 = 0.4 ——————- 0
0.4 * 2 = 0.8 ——————- 0
0.8 * 2 = 1.6 ——————- 1
0.6 * 2 = 1.2 ——————- 1
…………

0.3 * 2 = 0.6 ——————- 0
0.6 * 2 = 1.2 ——————- 1
0.2 * 2 = 0.4 ——————- 0
0.4 * 2 = 0.8 ——————- 0
0.8 * 2 = 1.6 ——————- 1
0.6 * 2 = 1.2 ——————- 1
